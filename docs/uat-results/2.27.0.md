# UAT — controller 2.27.0, firmware v2.19.0 and emOS v0.11

## About this report

**What:** user acceptance testing (UAT) is the last check before a release: does the software do what it says, on real hardware, the way someone would use it. Automated tests check the code; this checks the product.

**Why:** settings that saved and then did nothing have shipped before. Every EchoMuse release now gets this pass, and the report ships with it.

**How:** a script drives the dashboard in a browser and changes every setting, then reads each Echo to confirm it received and applied the change, and puts it back. An accessibility scanner checks every screen. A person then works through voice, music, buttons and pairing with the Echoes in front of them, while the logs are watched.

**PASS.** 45 dashboard controls checked on 4 real Echoes: 4 disabled, 17 received, 24 applied. Accessibility: 27 views, all clean (WCAG 2.1 AA, automated).

Guided steps with a person: 14 pass, 2 pass with findings, 3 not run.

**Versions.** This is the acceptance run for controller 2.27.0, firmware v2.19.0 and emOS v0.11. It was run on 2026-11-08 against the Early Access builds they are cut from: controller 2.27.0-ea.6 (after a 17.5-hour soak with no errors), firmware v2.19.0-ea.4 and emOS v0.11-ea.2. The GA builds are that code with the release's version number. Nothing was fixed during the run.

Echoes: `…1VVV` (Echo Dot 2nd gen, FireOS 5), `…15LE` (Dot, emOS, 32-bit kernel), `…0C95` (Dot, emOS, 64-bit kernel), `…035T` (Echo 2nd gen, emOS). This is the first GA run to include an Echo 2nd gen.

## Findings

Known issues in this release:
- **On the Echo Dot, a voice reply can crackle at 90% volume and above.** Heard on `…0C95` and `…15LE` at 90%; clean at 85% and 75% on `…0C95`. No playback underruns were logged, so this is the sound at the top of the range, where the new voicing drives the output chain hardest. To be fixed in a later firmware.
- **With music playing on one Echo, a nearer Echo of a different model can lose the wake word to it.** The tester stood nearer `…0C95`, which was playing music; `…035T` read 3.6 dB louder and answered. Loudness readings are not yet comparable between the Dot's and the Echo 2nd gen's microphones.

Not covered: the provisioning wizard (skipped this release; no freshly unlocked Echo on the bench), the firmware update offer for v2.19.0 (that release does not exist until this report is signed off; the update path ran throughout Early Access), Sendspin and Music Assistant grouping, the Bluetooth proxy, and talking over a reply while Home Assistant is unreachable (#417). The database migration was run on an empty database; the house Early Access controller has run the same migration on real data since 2.27.0-ea.2.

## How this was run

- One control fewer than 2.26.0: Speech boost (`eqLoudness`) was removed from the dashboard by #1026, when the new voicing took over its job.
- Controller image `ghcr.io/wilbowes/echomuse-controller:2.27.0-ea.6`, isolated rig (tools/uat/rig.py); Echoes attached over USB: `…15LE` (emos), `…0C95` (emos), `…1VVV` (fireos), `…035T` (emos).
- Config baseline `d44b4235a3a0` (tools/uat/baseline.json: shipped defaults plus its listed exceptions; every Echo following the fleet).
- Controls run 2026-11-08T00:25:15Z; accessibility scan 2026-11-08T00:21:53Z.
- Each control: changed in the browser, saved, read back from the API, then checked on the Echo (`/tmp/em-config.json`: received, and applied where its running config covers the key), then put back and checked again.
