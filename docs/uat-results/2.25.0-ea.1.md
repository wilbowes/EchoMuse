# UAT — 2.25.0-ea.1

## About this report

**What:** user acceptance testing (UAT) is the last check before a release: does the software do what it says, on real hardware, the way someone would use it. Automated tests check the code; this checks the product.

**Why:** settings that saved and then did nothing have shipped before. Every EchoMuse release now gets this pass, and the report ships with it.

**How:** a script drives the dashboard in a browser and changes every setting, then reads each Echo to confirm it received and applied the change, and puts it back. An accessibility scanner checks every screen. A person then works through voice, music, buttons and pairing with the Echoes in front of them, while the logs are watched.

**PASS.** 37 dashboard controls checked on 3 real Echoes: 17 received, 20 applied. Accessibility: 22 views, all clean (WCAG 2.1 AA, automated).

Guided steps with a person: 4 pass with findings, 9 pass, 1 pass after fix

## Findings

Fixed before release:
- **A fleet setting changed during a slow save was shown as saved and never sent.** Found by the rig on the Bluetooth proxy control; fixed in #676 and retested on the release image.
- **Volume-up on the Echo while muted unmuted at the button floor (37%)** and replaced the stored volume. Fixed in #678 (restores the old level plus one step); retested.
- **Provisioning wizard: tall steps clipped their own buttons, and the WebUSB notice was a wall of text.** Fixed in #676 (a stopgap until the wizard redesign).
- **Device Logs tab could not be scrolled by keyboard** (axe, all three Echoes). Fixed in #676; the release image scans clean.

Known issues in this release:
- **Music can drop out around a voice turn's duck**, and a long stall can drop the Echo's audio link for ~5 s. The controller paces music by a clock estimate that goes wrong after any gap; #671 (the Echo reporting its own buffer) is the fix, for the next Early Access release.
- **"Hey jarvis" false-wakes over music.** The speech gate keeps them from Home Assistant, so the cost is a few seconds of ducked music.
- **The emOS v0.9 upgrade notes are wrong**: re-running the wizard's build and flash also reinstalls GA firmware and removes a hand-written `controller.json`.
- **VVV's mute button light went out once while muted** (the mic stayed muted). Did not reproduce; cause unknown.
- Cosmetic: after volume-up unmutes, the ring shows one segment until the next press.

## How this was run

- Controller image `ghcr.io/wilbowes/echomuse-controller:sha-2d59231 (controls); ghcr.io/wilbowes/echomuse-controller:sha-0a763b7 (release recheck)`, isolated rig (tools/uat/rig.py); Echoes attached over USB: `G090LF11752215LE` (emos), `G090LF1180440C95` (emos), `G090LF1180571VVV` (fireos).
- Controls run 2026-09-27T05:22:38Z; accessibility scan 2026-09-27T06:14:02Z.
- Each control: changed in the browser, saved, read back from the API, then checked on the Echo (`/tmp/em-config.json`: received, and applied where its running config covers the key), then put back and checked again.
